## 0. 一句话定位

**持仓离场预警 = 现有形态识别引擎（`chanlun/pattern.py`）的镜像复用 + 持仓状态卡**。
买点报告告诉你"什么时候进"，持仓之后用同一套引擎告诉你"什么时候该走、能不能留底仓"。
不新造判断逻辑、不开新页面、不加扫描循环。

---

## 1. 背景

- 现有持仓模块：`data/positions.json`（Gitee 为权威源），字段 symbol / period / entry / 进场价。
- 用户持仓跟着监控报告走：报告响 → 进场 → 录入持仓（品种、级别、进场类型、价格）。
- 用户痛点：入场有体系，出场靠感觉。本系统 = **止盈/离场预警系统**（用户明确：不做止损系统，止损自管）。

---

## 2. 定稿原则（用户逐条确认）

### P1 买卖一致性（最高原则）

- 入场等**结构确认**，出场也等**结构确认**——卖点 = 本级别**二卖**确认。
- 一买抓不住所以不做 → 一卖同样抓不住，不追求卖在最高。二卖与二买完全镜像。
- 出场不用"结构破坏位"：那不在入场体系里，用了等于引入第二套没验证过的逻辑。规则一致性 > 落袋偏好。

### P2 三卖 = 无条件全平信号

- 三卖（次级别离开中枢后回抽不回，中枢定理三）是趋势确认，不赌。对底仓同样生效。

### P3 镜像复用，引擎双轨让走势选边

- 多头持仓 → 监听同品种同级别**卖出侧**信号；空头对称。
- A类（背驰系→二买二卖）/ B类（中枢系→三买三卖）双轨并行，二义性走势两条轨都挂着，走势选边。

### P4 有持仓才预警

- 没持仓的品种零开销。持仓 symbol+period 决定监听对象。

### P5 监控页一切照旧

- 矩阵、卡片、推送、事件流一个字不改。持仓期间本级别再报买点，监控页该怎么报怎么报；
  持仓状态卡只是**同步显示**引擎已有状态，不影响任何现有行为。

### P6 系统边界（用户 2026-10-13 晚明确）

- 本系统只做三件事：**① 本级别离场信号预警 ② 回调笔延续提示 ③ 留底仓（升级）提示**。
- 止损、保本价由用户自己判断执行，系统不做。

---

## 3. 离场规则（系统范围）

| # | 触发 | 动作 |
|---|---|---|
| 1 | 本级别**二卖**确认（黄线画出即报，见 §4） | 预警离场；若有升级标记 → 提示"可平半留底仓"（执行与否用户定） |
| 2 | **三卖**出现 | 预警无条件全平（含底仓） |
| 3 | 进场回调笔**延续**（假回调，§5） | 提示"止盈预期要变" |
| 4 | **可升级**标记（§6） | 提示"本级别卖点后可留底仓，过户给 X 分" |

背景知识（系统不实现，作文档留底）：止损 = 前买卖点结构破坏位（二买→一买背驰点破坏；
三买→前中枢上沿跌回）；保本价 = 用户见本级别反向顶分型自行上移。

---

## 4. 预警标准与数据源（Q2/Q3 定稿）

- **标准 = 黄线画出来的那一瞬间**：`_effective_bis`（完成笔 + 进行中笔，同向延伸替换端点 /
  反向跨度≥4 即成笔），与矩阵卡片、成笔徽标同一数据源同一时刻。
- **单一档，不分两级警报**：不存在"先预警后离场"两次报，信号画出来就报一次（后续状态变化跟随更新，
  与现有卡片原位更新机制一致）。
- 回调笔延续判定同源 `_effective_bis`（黄线延伸/反向笔被吃）。

---

## 5. 进场后的延续提示

三买回调笔进场后（空头镜像），引擎持续判定该笔状态：

1. **回调笔是假的（延续）**：黄线延伸/反向笔被吃 → 不用等回调了，但止盈预期要变 → 提示。
   这是好事但用户要知道。
2. **回调笔没走完**：进场价可能只在这笔回调一半位置，浮亏扩大——用户自己看盘处理，
   系统不做额外判断（止损自管）。

---

## 6. 留底仓提示（"升级"机制）

### 6.1 本质（用户定稿）

> "级别升级最大的目的就是告诉我留底仓——本级别卖点出现之后卖掉时，可以留一部分仓位做底仓，去做更大的级别。"

- 不保证各级别买点在时间上串起来（3分进场可能5分就报了，利润还不够看）——它只是**提示**，不是自动操作。
- 平仓永远按**当前生效级别**的买卖点；用户真正全平后会自己结束单子，系统不需要管递进链的终点。

### 6.2 判定 = 完全复用引擎（Q4/Q5/Q6 定稿，零新逻辑）

- **条件**：持仓品种的**任何更大级别**（3/5/15/30/60 分中比持仓周期大的全部）出现**同方向**买点评估状态。
- **2 倍逻辑不用新写**：引擎 B类形态自带 `PATTERN_RATIO = 2.0` 幅度过滤（`pattern.py` C2），
  大级别买点的评估结果里已经包含了用户想要的"走势类型走出足够幅度"判定。
- **标注规则**：更大级别同方向买点**确认/触发**（即矩阵格子亮出 A类确认/B类触发）→ 持仓卡标
  "可升级→X分"；多个级别同时满足 → **取最大的级别**标注。
- **实时可逆**：大级别状态被破坏（假确认作废、格子熄灭）→ 升级标记同步取消。
  与矩阵"可逆不变"语义一致。
- **递进**：底仓持有期间更大级别又满足 → 标注跟随更新（15→30→60），到 60 分封顶（无日线）。
  不需要特殊递进处理——底仓永远只听"当前标注级别"的信号。

### 6.3 架构（Q9 定稿：零新增循环）

- **不建任何新扫描循环**。现有 evaluator 每轮扫描（含启动基线）评估到持仓品种的周期时，
  顺带把该品种该周期的信号状态写入持仓状态；评估到持仓品种的更大级别时，顺带算升级标记。
- 需保证：持仓品种的上级周期也在评估范围（即使该格子不在用户监控矩阵里）——只对持仓品种补评，
  数量最多 4 品种 × 若干上级周期，量小。
- 状态变化才推送（沿用现有去重闸门/指纹机制精神），不重复轰炸。

## 7. 呈现方案（提案，待用户确认后实现）

用户否掉独立新页面（屏幕有限，一面要实时看单）。用户意向：就在监控页现有持仓列表上做。
两个候选：

### 方案甲（推荐）：持仓卡升级为"持仓状态卡"，单卡两段式

现有持仓小列表（≤4 张卡）加高加宽，每张卡分两段：

```
┌──────────────────────────────────┐
│ 棉花 MA609 · 30分 · 三买 · 2532   │   ← 上段：现状不变（品种/级别/进场点/操作）
│ [编辑] [平仓]                     │
├──────────────────────────────────┤
│ ⏺ 监控中 · 30分 无卖点            │   ← 下段：实时状态区（紧凑徽标行）
│ ⬆ 可升级 → 60分 (B类触发)         │
│ ⟳ 回调笔延续 · 止盈预期变          │   ← 有才显示，无则不占行
└──────────────────────────────────┘
```

- 下段徽标配色沿用矩阵卡语义（A类/B类、多/空同色系），一眼和矩阵对应。
- 状态行内容：本级别卖点状态（`无卖点` / `A类空 确认` / `B类空 触发`）、升级徽标（可逆）、
  延续提示（有才显示）。
- 点卡片 → 跳该品种详情页。
- 手机端 m_list 持仓列表同步加一行状态（复用同一状态数据，后续迭代）。

**优点**：一个位置看完持仓+状态；不加新面板；卡片数量不变。
**缺点**：单卡信息密度高，4 张卡时列表要占更多纵向空间。

### 方案乙（备选）：持仓卡不动，旁边"复制一张监控式小卡"

每个持仓旁并排一张缩小版监控状态卡（相当于把矩阵卡复制一份显示该品种该级别状态）。

**优点**：持仓卡零改动，状态卡可完整复用矩阵卡渲染。
**缺点**：面板宽度翻倍；两张卡需要人眼配对；信息冗余。

## 8. 中枢扩展的二卖死角（查证结论，实现时回归验证）

场景：离开中枢向上新高 → 回调一笔 → 反弹不破前高，三笔重叠成新中枢。
前高不属于新中枢；中枢区间 = [回调笔低点， 次高点]。

- **前高带顶背驰**：反弹笔高点 = 标准二卖（次高点本来就是中枢组成部分），A类空可判。
- **前高无背驰**：无一卖则无二卖，该段只是上涨中继新中枢，卖点只剩三卖
  （破下沿 + 回抽不回，中枢定理三）——"二三卖重合"实战版 = 等三卖。
- 引擎 A类/B类双轨并行（P3），此场景两轨都挂观察，走势选边。
- **实现阶段须回归验证**：新中枢形成导致笔归属变化后，A类空反弹判定能否正常出卡（拿实际案例）。

## 9. 与现有系统的衔接点（实现参考）
