# RAG 知识库系统设计（v0.2 定稿）

> 定位：Agent 系统的"图书馆"——周复盘分析师与留言接口的知识检索层。
> 原则沿用老规矩：先对齐后动工。v0.2 已锁定全部关键决定（见文末），进入施工阶段。

---

## 1. 背景与动机

Agent 系统（`agent/`，周复盘分析师）目前依赖数据包 + prompt 完成定量归因，但有两类知识问题解决不了：

1. **体系术语的口径问题**：本系统在缠论基础上定义了自己的术语口径（买卖点分级、形态标记等），
   模型对这些"系统内部黑话"只能靠 prompt 里硬编码的短定义，深度受限。
2. **缠论原典知识学得浅**：三类买卖点、背驰、中枢、级别递归等定义散落在原文长文中，
   模型内置知识容易似是而非，回答缺乏一手出处。

**解法：给 Agent 接一个知识库（RAG）。回答前先检索权威知识源，回答必须带出处（第几课），
查不到就明说"知识库无相关内容"。**

语料分两层：

| 层 | 内容 | 性质 |
|---|---|---|
| 公共层（一期） | 缠中说禅原文（新浪博客连载，108 课） | 缠论体系唯一一手出处 |
| 私人层（二期） | 本系统复盘沉淀：体系疑问清单结论、术语口径、极值教训 | 模型不可能见过的私有知识 |

## 2. 为什么选缠论原文作为公共语料

1. **一手出处**：108 课原文是缠论体系定义的权威来源，检索命中即原文，
   天然携带精确引用（"缠论第 62 课"），与 Agent 现有的"引用必须带出处"纪律无缝衔接。
2. **真实非结构化形态**：博文正文混有博主闲聊、网友回复、时效性行情内容与排版断裂——
   这正是企业语料接入环节面对的真实形态。清洗与切分按生产标准执行，不做玩具化简化。
3. **规模适中**：数十万字，全流程（接入→清洗→切分→Embedding→入库→检索→评估）
   可在单机完整落地，且每个环节的算法与企业生产环境同构（差异仅在规模与工程配套，见 §4）。

**关于"为什么不把全文塞进长上下文"**：数十万字已逼近主流模型上下文上限，直接塞全文
单次成本高、检索精度随长度衰减（lost in the middle）、无法增量更新、无法精确引用出处。
RAG 承担"知识检索"环节，与长上下文、微调是组合关系而非互斥关系。

## 3. 部署形态：进程内本地库（已定）

| 方案 | 适用场景 | 本系统 |
|---|---|---|
| **进程内本地库**（Chroma 持久化到磁盘） | 单机、单人、语料中小规模 | ✅ 一期采用 |
| 独立向量库服务（Milvus / ES / PGVector） | 多服务共用、亿级向量、权限过滤 | 概念了解，暂不引入 |
| 云托管 API（托管 embedding + 检索） | 多端访问、免运维 | 备选，接口已预留切换 |

选本地的理由：服务本就单机部署，Agent 调用为进程内函数调用，知识库无独立部署的必要；
索引即磁盘目录，随项目同步，备份与多机迁移成本为零。
**索引目录不入 Git，新机器克隆后零手动步骤**：首次检索检测到索引为空时自动重建
（清洗语料已入库保证可复现；首次需下载 embedding 模型，国内网络设 `HF_ENDPOINT=https://hf-mirror.com`）。

## 4. 与企业生产链路的同构性

本系统一期链路与企业生产 RAG 链路逐环节对应，差异仅在规模与工程配套：

| 环节 | 企业生产 | 本系统一期 |
|---|---|---|
| 语料接入 | 多数据源对接、定时增量、权限过滤 | 爬虫一次性抓取 + 增量接口预留 |
| 清洗切分 | 清洗流水线 + 结构化/父子切分 | 清洗纯函数 + 父子 chunk（§6） |
| Embedding | 批量/流式向量化服务 | 本地 BGE 批量向量化（§7） |
| 向量库 | Milvus / ES 分片集群 | Chroma 单机持久化 |
| 检索服务 | 独立检索服务 + 监控 | 进程内函数 + 查询改写（§8） |
| 评估 | 线上 badcase 回流 + 离线题库回归 | 检索题库 recall@k（§10） |

## 5. 架构

```
rag/
  __init__.py
  ingest.py       # 语料接入：抓取/读取 → 清洗 → 切分 → Embedding → 入库
  retrieve.py     # 检索：查询改写 → 向量召回 → 返回带出处片段
  config.py       # 模型/路径/参数集中配置（embedding 可切换）
  evals.py        # 检索质量题库与跑分（§10）
data/
  rag_index/      # Chroma 持久化目录（不入 git）
  rag_corpus/     # 清洗后语料（入 git，保证索引可复现）
```

**接入方式**：在 `agent/tools.py` 新增工具函数 `kb_search(query) -> [{片段, 出处, 分数}]`，
按现有 schema 工具规范注册。周复盘分析师与留言接口共用同一工具，Agent 循环无需改动。

**出处格式**（沿用幻觉抑制纪律：引用必须带 source）：

```json
{"chunk": "第三类买卖点的定义……", "source": "缠论第62课", "score": 0.83}
```

## 6. 切分与清洗

**父子 chunk（两层切分）：**
- **父块 = 一课**：108 课每课一个父块，metadata 带 `{课号, 标题}`。检索命中后返回整课，
  保证模型拿到完整上下文而非孤立段落。
- **子块 = 课内段落**：按段落切 200–500 字子块，检索以子块为粒度（粒度细，召回准）。
  即"子块负责找得准，父块负责给得全"。

**清洗范围**：博主闲聊段、网友回复、时效性行情叙述、排版断裂、图片占位符。
清洗规则实现为纯函数，被剔除内容记入 `rag_corpus/clean_log.md` 留痕，支持审计与规则迭代。

## 7. Embedding 选型（默认本地 BGE）

Embedding 模型只负责"文字 → 向量"的转换，不是对话模型。候选与对比：

| 方案 | 成本 | 数据出域 | 离线重建 | 依赖 |
|---|---|---|---|---|
| **本地 BGE**（bge-small-zh-v1.5） | 零 API 成本 | 不出本机 | ✅ CPU 分钟级全量重建 | sentence-transformers |
| 托管 embedding API（智谱 / OpenAI / Jina 等） | 按量计费 | 需联网上传 | ❌ | 网络与配额 |

**默认选本地 BGE**：108 课规模下全量重建为分钟级，无 API 成本；模型接口在 `rag/config.py`
抽象为可切换，后续如需托管服务或多语言（bge-m3）可平滑迁移。

## 8. 查询改写与术语映射（2026-11-15 双层检索完工）

检索查询词来自 Agent 上下文，含系统自定义术语（如分级卖点口径），而语料中为缠论原词。
`retrieve.py` 维护术语映射表，检索前先做查询改写（query rewrite）：

```
系统口径术语 → 缠论原词展开（如：分级卖点 → 一/二/三类买卖点 + 背驰 + 中枢）
```

**私人知识层已落地**：同库独立 collection（`private`），与公共层并行召回、按相似度合并。
私有语料三类（全为结构化数据，免清洗管线）：体系疑问清单（问题原文+结论）、周复盘（三问回答/行动项）、
手写口径术语表（`data/rag_corpus/private/glossary.md`，改完跑 `python -m rag.ingest embed-private` 即生效）。
**私有语料属用户数据，不入版本库**：glossary.md 在 .gitignore 中排除，仓库随附中性模板
glossary.template.md，文件缺失时入库程序自动从模板生成——克隆者用自己 reviews.json 的复盘数据
+ 自建口径表，即可把私有阅览室换成自己的体系，代码零改动。
检索结果出处按层区分：原文=课号，私有=类别+日期，模型据此标注引用。

## 9. 接入点（已定：周复盘 + 留言接口）

- `kb_search` 注册为 Agent 工具，周复盘分析师在生成建议前可查知识库并引用原文。
- **留言接口为一期验证入口**：自然语言直问（如"三类买卖点的完整定义是什么"），
  即时验证检索质量与出处正确性，无需等待复盘数据。

## 10. 评估体系（2026-11-15 完工）

`rag/evals.py` 三层评估 + 负例 + 回流，题库在 `rag/eval_bank.json`（badcase 直接加条目即成回归用例）：

| 层 | 判定方式 | 防的失败 |
|---|---|---|
| 检索层 | recall@1/@3（期望课号人工标注） | 搜不到权威出处 |
| 引用核查 | 答案课号 ∈ 模型实际检索到的课（纯程序判定） | 编造出处 |
| 忠实度裁判 | LLM 评审答案是否忠于检索片段（可选 `--judge`，429 自动容错剔除分母） | 片段外添加事实 |
| 负例 | top1 相似度低于阈值（0.55）应不命中；拒答关键词判定 | 不懂装懂 |

命令：`python -m rag.evals`（检索层，快）/ `full [--limit N] [--judge]`（含生成层）/ `add "问题" --expect 61,62 [--neg]`（回流）/ `history`（基线对比）。
历史留痕：`data/rag_corpus/eval_history.jsonl`。
首版基线（2026-11-15）：recall@1=70%，recall@3=100%，负例拒答 100%，引用覆盖率 100%，编造出处率 0%。
方法论备注：引用核查的基准必须是**模型实际检索到的课**（通过包装工具执行器记录），而非评估器自己按原句检索的结果——否则模型自主换词检索到的合法出处会被误判为编造（首版曾因此误报 50% 编造率，已修正）。

## 12. 已锁定决定（v0.2）

1. **语料**：直接抓取缠中说禅博客原文，不使用二手整理版（清洗工作按真实语料标准执行）。
2. **部署**：本地进程内 Chroma，索引持久化 `data/rag_index/`。
3. **Embedding**：默认本地 BGE（bge-small-zh-v1.5），接口抽象可切换。
4. **接入**：周复盘 Agent 与留言接口同时接入，留言接口为一期验证入口。
5. **私人知识层**：已落地（2026-11-15）——同库独立 collection，双路召回按分数合并，语料=体系疑问/周复盘/口径术语表。
6. **出处纪律**：回答引用必须带课号出处，检索无命中时明示"知识库无相关内容"。
