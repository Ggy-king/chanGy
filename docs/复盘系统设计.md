# 复盘系统设计（v0.2 定稿，2026-10-17）

> 定位：列表页第三大模块。**回测=验证过去，监控=发现当下，复盘=进化自己**。
> v0.2：用户已答全部 7 问（见文末"已锁定决定"），新增"体系疑问清单"环节。

---

## 一、核心哲学：复盘不是写日记，是"机器审计 + 认知固化 + 行动闭环"

**复盘的"事实采集"100% 由机器完成（数据都在，不需要人填），人只做两件机器做不了的事——确认主观状态、做下周的决策。**

四层框架：

| 层 | 问题 | 谁干活 |
|---|---|---|
| ① 市场复盘 | 市场给了什么？ | 机器 |
| ② 系统复盘 | 系统抓住了吗？（统计并入） | 机器 |
| ③ 执行复盘 | 我违规了吗？人性上呢？ | 机器出草稿，人确认 |
| ④ 行动闭环 | 下周改什么？上周改的执行没？ | 人 |

第 ④ 条是机构复盘的核心：**产出不是感想，是最多两条可执行修改，下次复盘第一屏先检查执行。** 没有闭环，复盘退化成每周忏悔录。

---

## 二、日复盘：不是日记，是"审计报告 + 已阅"

系统每天收盘后自动 diff"信号流 vs 交易流水"，生成审计报告，用户唯一动作 = 扫一眼 + 点"已阅"（10 秒）。连续已阅天数显示在页头。

自动审计项：

| 审计项 | 判定逻辑 |
|---|---|
| 冲动单 | 开仓前 30 分钟内，本品种本级别无任何确认/候选信号 |
| 提前单 | 开仓时信号最高状态仅为候选/观察，未到确认 |
| 持仓越界 | 同时持仓 >4 个；同赛道重复持仓（软提示，见赛道映射） |
| 单笔风险 | 止损距离折算风险 > 总资金 2%（资金基数在 secret.py 配置） |
| 止损执行 | 亏损单平仓价 vs 一键止损线偏离超阈值 |
| 浮盈破例 | 同品种已有持仓时再开仓（变相加仓） |
| 换仓续杯 | 平仓 → 同品种短期重开（尤其级别升级）→ 标注"疑似续杯" |

输出：绿灯日（全合规，一行字）/ 黄灯日（疑似，可"确认误报"）/ 红灯日（明确违规，记录在案）。

**漏单判定：取消**（用户定稿 2026-10-17："看到信号但选择不做"是正当决策）。保留一个纯统计"确认信号→开仓转化率"供系统自察，默认不显示、永不判违规。

## 三、周复盘：机器出草稿，人答机器答不了的（≤2 小时上限）

周一开盘前自动生成上周《交易审计表》。用户五问落地：

| 用户原问 | 落地方式 |
|---|---|
| 1. 每笔是否由"系统信号+人工确认"触发？ | 自动判定冲动/提前，人工复核例外 |
| 2. 止损都执行了吗？该走没走？ | 自动判定（平仓价 vs 止损线）+ 持仓离场信号汇总 |
| 3. 单笔≤2%、≤4 个不相关品种？ | 自动判定（资金基数 secret.py + 赛道映射软提示） |
| 4. 浮盈破例（加仓/提前止盈/拿不住/手痒）？ | 半自动：加仓/多做自动检测；持仓时长对比复用统计页；主观留一个选择题 |
| 5. 焦煤 5分→15分 换仓按独立新单管理？ | 自动检测换仓行为 → 标"疑似续杯" → 人工勾选"独立管理/承认续杯"（通用规则：任何同品种升级换仓都适用，不止焦煤） |

人工部分结构（总计 ≤10 个交互）：
- 审计例外复核（有则勾选，无则跳过）
- 主观三问（每题一句话）：①本周最难忍的冲动 ②最满意的一个执行 ③下周最想改的一件事
- **体系疑问（见下节）**

存档 `data/reviews.json`（周 key=ISO 周），提交后不可改（防事后美化），只能追加补充说明。**暂不做 Gitee 同步**（用户定稿：持仓已同步，复盘纯本机）。

## 四、体系疑问清单（v0.2 新增环节，用户 2026-10-17 提出）

**动机**：复盘不只复盘"执行"，还要复盘"体系本身"——系统里没被解决的小问题（如"能否在更小级别提前确认本级别底分型"）需要被强制浮出水面。

**机制：强制思考，不强制产出。** 每周复盘固定一屏：

1. **强制提问**："本周体系有没有让你不舒服/存疑的地方？"——必须二选一：写下疑问，或明确点"本周无"（防止惯性跳过）。疑问写进**体系疑问清单**。
2. **系统投喂线索**（机器主动提）：审计与统计里出现的异常自动变成"疑问候选"——某组合样本≥10 但期望值异常、某品种连续数周零信号、某审计项反复误报。候选只提示，是否立项由人定。
3. **疑问生命周期**：待研究 → （关联回测页验证）→ 已解决（附一句结论）或 已否决（附原因）。**挂起超过 4 周的疑问自动标黄**——要么值得排期研究，要么删掉，不许永远躺着。
4. **月复盘清点**：本月新增几问、解决几问、积压几问——"体系自我修复的速度"本身成为一条指标。

> 这个环节的本质：把"随手想到的灵感"从会丢失的短期记忆，变成有生命周期的资产。缠论上这叫"走势终完美"，工程上这叫 issue tracker——复盘页就是体系的 issue tracker。

## 五、月复盘：判决与进化

月初自动生成，四板块：

1. **统计全量**（统计页整体能力，复盘页内呈现）
2. **体系判决**：样本≥10 且期望值持续为负 → 亮牌"该停/该改"；≥30 且为正 → "可加观察权重"。判决必须过样本门槛
3. **违规率趋势**：周存档的违规次数随周变化——人性改善本身是曲线
4. **极值复盘 + 行动项**：自动挑本月最大盈/亏两笔（附信号快照）各写一句"教会了我什么"；行动项 ≤2 条

## 八、赛道映射表（已定：做，但只做"软提示"）

用户顾虑有道理（16 品种本来就按不相关设计的），但**当前组合里确实存在同大类驱动的对**：液化气+甲醇（原油链）、纯碱+PVC（地产链）、甲醇+尿素（煤化工）。用途收敛为一条：

- **只做软提示**："当前持仓中 X 与 Y 同属 Z 驱动，合计风险已超单赛道预算"——不算违规、不进红灯，只进日审计黄灯提示
- 映射表放 config.py（用户可改），覆盖当前 16 品种 + 预留未来赛道空槽（贵金属/油脂油料/新能源等，注释形式待资金到位）

## 九、分期实施

- **第一期**：`/pc/review` 页面骨架（四 Tab）+ 周复盘审计表（冲动/提前/越界/止损执行/换仓判定）+ 体系疑问清单 + 月复盘静态报告 + 列表页按钮 + 日审计报告生成（pattern_loop 收盘时算好存档）
- **第二期**：已阅打卡连续天数、行动闭环检查屏、市场环境标注、疑问候选自动投喂
- **第三期**：违规率趋势曲线、体系判决自动化、（若接上只读账户）真实资金审计
