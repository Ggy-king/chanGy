# Agent 系统设计（v0.2 —— 关键四问已定，剩三个默认项可改）

> 2026-10-17 创建，同日对齐 v0.2。原则：**周复盘功能全部齐了之后才动工**，本文档先对齐，不写代码。
> 前置共识：复盘系统目前能"审计"（机器判对错），但复盘里的人工文字（问答、行动项、极值教训）是死的，
> 机器读不懂。用户要的不是又一个统计页，而是"有人替我把定量数据和定性文字放在一起，读出点东西来"。

---

## 1. 用户原始诉求（原话归纳）

1. **系统表现侧**：一键把本周的胜率、盈亏比、合规性、违规分布等全部打包，交给大模型，直接生成建议。
2. **人性侧（更重要）**："我除了想知道系统做得怎么样，其实我还想知道我人性这个方面有没有欠缺"——
   复盘问答里写的文字、处置时的犹豫、极值复盘的教训，让模型去读，给出心态层面的观察。
3. **为留言接口做准备**：将来在留言框说"查一下 10 月 12 号那周的数据，有什么建议"，Agent 能被自然语言调用。
4. 节奏要求：先建 `agent/` 文件夹、先对齐、一个功能一个功能做，**不草率动手**。

## 2. 值不值得做？（诚实评估）

**值得，理由：**
- 复盘系统已经积累了三类高价值数据：结构化审计项（三级判定+处置）、交易流水（开平仓+盈亏）、定性文字（问答/教训/疑问清单）。
  现在它们各存各的，唯一能把三者"放在一起读"的是用户自己——恰好是复盘时最累、最容易自欺的时候。
- 大模型擅长的事：跨维度归因（"违规集中在连亏之后"+"你在问答里写了拿不住"→ 指出模式）、把数字翻译成人话。
  这不是炫技，是补上"量化是死的"这半边。

**风险（设计时要压住）：**
- **幻觉**：模型可能编造数据里不存在的事实。→ 对策：prompt 强制"只引用数据包里的字段，引用需带出处（如 trade_id）"，无据可依时明说"数据不支持结论"。
- **建议泛泛**："注意风险控制"这种废话。→ 对策：数据包里带聚合（违规时段/品种/连亏序列），prompt 要求建议必须落到"可执行的下一步"，且数量限 3 条以内。
- **越权**：Agent 只**读**和**说**，不写任何交易/审计数据。建议存档后由用户标记"采纳/不采纳"，形成反馈闭环（二期）。

## 3. 架构草案

```
agent/
  __init__.py
  llm.py          # 模型接入层：唯一的联网出口，可换模型供应商（见 §4）
  tools.py        # 本地数据工具：每个工具=一个纯函数，输入参数→输出 JSON（无副作用）
  weekly_analyst.py   # 第一个 Agent：周复盘分析师（组合工具取数 → 拼 prompt → 调 llm → 解析存档）
  prompts.py      # 所有 prompt 模板集中在此（可迭代调优，不动代码）
```

**调用链**：页面按钮 → `POST /api/agent/weekly`（week 参数）→ weekly_analyst 取数（复用 server 现有函数，
不重复造轮子：`_all_trades / _audit_day / api_review_weekly 的聚合 / reviews.json 的问答与处置`）→
组装数据包 JSON → prompts 模板 → llm.chat() → 建议文本 → 存 `reviews.json → weekly[wk].agent` → 返回页面。

**数据包 schema（v0 草案，给模型看的东西要刻意设计）：**
```jsonc
{
  "week": "2026-W42",
  "trade_flow": [/* 逐笔：品种/级别/方向/开仓小时(无分钟)/价格/盈亏/判定/该笔处置结果 */],
  "compliance": { "compliance": 79, "violation": 5, "certain": 0,
                  "vio_syms": {...}, "vio_hours": {...} },
  "risk_profile": { "max_risk_pct": 1.8 },   // 单笔风险占比，不发 CAPITAL 原始值
  "consecutive_loss_seqs": [/* 连亏序列：用于"报复性交易"检测，如 [{-320,-100},{+50,-680}] */],
  "answers": { "q1": "...", "q2": "...", "q3": "..." },   // 用户亲笔文字——人性分析的主料
  "actions": ["..."],                                       // 上周行动项（检查是否做到）
  "lessons": { "best_note": "...", "worst_note": "..." },   // 极值复盘教训
  "questions_open": [/* 体系疑问清单在办项 */]
}
```

**Prompt 框架（v0 草案）：**
- 角色：交易纪律教练，不是分析师——只问过程和人性，不预测行情、不给买卖建议。
- 输入：上述数据包 + 固定分析框架（①执行纪律模式 ②人性/心态模式 ③系统可能的问题 ④最多 3 条下周可执行建议）。
- 硬约束：禁止荐股荐合约；禁止评价单笔盈亏好坏（只评决策过程）；每个论断必须能指向数据包字段。

## 4. 对齐结果（2026-10-17 用户拍板）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 模型选型 | **智谱 GLM-4-Flash**（免费额度、国内直连）；`llm.py` 做成可换供应商，将来能切 DeepSeek/Ollama |
| 2 | 隐私边界 | **可发云端，但做"小时级隐性脱敏"**（见 §4.1，用户提出思路、AI 决断定稿） |
| 3 | 触发方式 | **页面按钮手动触发**——复盘是主动仪式，也省额度；不做自动跑 |
| 4 | 建议存档与展示 | 按我的倾向定：存 `weekly[wk].agent={text,model,created,adopted?}`，显示在合规报告下方；回看上周建议时加"采纳/没做到"标记（采纳闭环，实现时如嫌重可先砍标记） |
| 5 | 人性分析数据范围 | 按我的倾向定：文字（问答/教训/疑问）+ 小时级行为序列（连亏后开仓间隔、违规时段）——分钟级已脱敏，无侵入感 |
| 6 | 验收标准 | **先跑通再说**——生成质量可以慢慢调 prompt，先把链路跑起来 |
| 7 | 费用/频率上限 | 手动触发天然限频；失败重试 1 次；单次超时 30s 直接报错不给半截结果 |

### 4.1 隐私决断（定稿）

**技术事实**：LLM API 无状态、单次独立请求、不对用户输入训练——"积累几百笔反推策略"不成立；
且期货公司/交易所握有完整报单流，发聚合数据的边际风险极小。

**脱敏方案（采纳用户思路 + AI 微调）**：
- 交易时间**只保留小时**，抹掉分钟（分钟对分析零增量）
- **小时必须留**：违规时段/疲劳时段/报复性交易检测全靠小时聚合，砍到"天"这条能力就没了
- 价格、品种、盈亏、日期、复盘文字：保留
- **资金总量（CAPITAL）不发**，只发"单笔风险占比 %"——数字脱敏，分析等价
- 实现位置：`agent/tools.py` 的 `_pack()` 一个函数收口，将来改口径只动它

发出去的数据：`品种 / 小时 / 价格 / 盈亏 / 判定 / 你的文字`。

## 5. 分期

- **Phase 0（现在）**：本文档对齐，回答 §4。
- **Phase 1（周复盘齐了之后）**：`weekly_analyst`——按钮触发、单次跑完、建议存档展示。只读，无自动触发。
- **Phase 2**：留言查询 Agent——自然语言 → 关键词/意图 → 调用 Phase 1 同一套 tools（"查 10 月 12 号那周"→ week 参数 → 数据包 → 也可以顺带生成建议）。这一步才考虑"Agent 调本地工具"的完整形态。
- **Phase 3（远）**：账户接入量化接口后，误判统计、实时盯盘心态提醒等才有数据基础（此前已定稿：误判现在不统计）。

## 6. 已定稿的相关决策（防止跑偏）

- 三级判定：certain / suspect / info；冲动单默认疑似（录入延迟常误判）。
- 【系统误判】按钮的价值是**逼用户回看当笔心态**，不做统计不给建议——等接入实盘账户再统计。
- 周复盘只问过程不问盈亏；月复盘金额已默认打码（防手痒，点眼睛临时看）。
- 复盘的仪式感优先于自动化：Agent 是"教练"，不能变成"替你复盘的机器"。
