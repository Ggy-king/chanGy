# 缠论中枢状态流程 · 详细分析与前端展示方案

> 状态：设计文档（暂不写代码）
> 日期：2026-10-04
> 目的：把流程图的每一步、每种分支彻底分析清楚，并规划将来在 K 线图上的展示形式，为后续实现中枢算法与前端标注做准备。

---

## 一、已确认的核心定义

| 概念 | 定义（已与用户确认） |
| --- | --- |
| **中枢** | 本级别走势类型中，由至少三笔重叠区间构成的价格区间 |
| **中枢识别** | 相邻三笔的价格区间重叠即可：每笔取其**两端点价格**（起点价、终点价）构成的高低范围，三笔区间有公共重叠即成中枢（已确认：用笔端点区间，标准笔，3笔重叠就行，不涉及K线实体） |
| **中枢大小** | 中枢区间的高度 = 中枢最高点 - 中枢最低点 |
| **0（中枢内）** | 当前价格位于中枢区间内部，无方向，等待离开 |
| **1（离开中枢）** | 价格顺势离开中枢，出现突破方向的一笔 |
| **2 / 等待2** | 与离开方向相反的**一笔回调**。只要这一笔**刚刚形成**，就开始算"发生2" |
| **2买卖点** | 严格出现在**原中枢的上沿或下沿** |
| **3买卖点** | 回调笔**不进入**原中枢时形成 |
| **中枢背驰** | 原中枢被破坏后的特殊分支（详见第四节） |
| **1+2（中枢中继）** | 背驰分支中，新走势已有中枢支撑后再次离开的状态 |

### 关键原则：往下推一步

- 系统永远只提示**下一个步骤**会走到的分支，不做更深的推演。
- 只要状态描述里出现**"参考原中枢边沿"**这样的字眼，就意味着：
  1. 当前价格在**中枢内部**；
  2. 此时就应该**立即提示**"要在中枢边界进行买卖"的意图；
  3. **不是**等价格真正走到边沿位置才提示——那就是推两步了，违反原则。

## 二、主流程逐步分析

### 2.1 状态 0：价格在中枢内部

- **现象**：最新笔仍在中枢区间内运动。
- **含义**：本级别当前无方向，中枢震荡中。
- **下一步候选（只推一步）**：
  - 价格顺势离开中枢 → 进入状态 1；
  - （其余复杂情况不提示）
- **提示文案示例**：`当前：中枢内震荡 · 等待离开`

### 2.2 状态 1：价格离开中枢

- **现象**：出现一笔顺势离开中枢区间。
- **判断**：比较离开幅度与**中枢大小（区间高度）**：
  - **离开幅度 < 中枢大小** → 走"小于"分支；
  - **离开幅度 > 中枢大小** → 走"大于"分支。
- **下一步候选（只推一步）**：等待反方向回调一笔形成（状态 2）。
- **提示文案示例**：
  - `当前：1 离开中枢（幅度<中枢） · 等待回调`
  - `当前：1 离开中枢（幅度>中枢） · 等待回调`

### 2.3 状态 2：反方向回调一笔刚形成

- **触发**：与离开方向相反的一笔回调**刚形成即算**，不用等它走完。
- **注意**：从这一刻起，系统开始监控回调是否进入原中枢。

### 2.4 回调结束后的分支判断

| 回调结果 | 判定 | 状态走向 |
| --- | --- | --- |
| 回调**不进入**原中枢 | 3买卖点形成 | 标注"3买/3卖" |
| 回调**进入**原中枢 | 回到中枢震荡 | 状态归 0 |

## 三、2买卖点的提示时机（重要）

- 流程图中"参考原中枢边沿作为2买卖点"这一支，出现在**价格位于中枢内部**的阶段。
- 因此**一旦判定价格在中枢内部**，系统就应该提示：
  > "下一步：若离开后回调不进中枢 → 在原中枢边沿做2买卖点"
- **不是**等价格到达边沿才提示。边沿只是入场位置的严格定义，提示本身要提前一步给出。

## 四、中枢背驰分支（详细分析）

### 4.1 前提场景

1. 本级别已经走了一个**向下走势类型**；
2. 走到了该走势类型的**最后一个中枢**；
3. 中枢之后又走了一笔**向下破坏**，离开了原中枢；
4. 但这一笔**直接收上来，重新收进原中枢之内**。

此时，把这一笔看作**向上走势类型的第一笔**。

### 4.2 向上第一笔的两种可能

#### 情况 A：第一笔直接破坏了原中枢

- 现象：向上的这一笔**直接破坏了原中枢**（穿透了中枢的边界）。
- 状态：此时向上走势类型**只有一笔**，尚未构成中枢。
- **下一步候选（只推一步）**：只能走"2"——即等待回调。
- 状态标记：`2`。

#### 情况 B：第一笔没有破坏原中枢

- 现象：向上第一笔未能破坏原中枢。
- 含义：意味着要在**原中枢之内**形成**新的中枢**。
- 此时监控对象切换为**这个新中枢**。
- 几何约束：**新中枢一定在原中枢的下方**（若在上方，说明第一笔已经破坏了原中枢，与前提矛盾）。
- 后续关键点：**第三笔必须破坏原中枢（例如上沿位置）**。
  - **若第三笔破坏了原中枢**：
    - 由于此时已经有**上升走势类型的新中枢作为支撑**；
    - 状态标记为 **`1+2`**——即"中枢中继"：正在构建一个新中枢；
    - 下一步候选：等待回调（2）。
    - **提示内容（已确认）**：此时提示的是"**回调若不进新中枢 → 3买卖点**"，**不是**"正在形成新中枢"。"中枢中继"只是状态名，提示永远按流程图下一步的买卖点指向走。
  - **若第三笔仍未破坏原中枢**：
    - 内部可能形成中枢扩展、中枢延伸等复杂结构；
    - **本系统不考虑这种情况**（唯一判断标准就是：必须破坏下降走势类型的最后那个中枢）。

### 4.3 为什么走到 1+2 就自然对应"中枢中继"

- 破坏原中枢的那一笔，是在**已有新中枢支撑**的条件下发生的；
- 它意味着本级别正在构建**新的中枢**（中枢中继）；
- 破坏之后价格仍需回调 → 所以状态必然落在 **1+2**：
  - `1` = 离开（破坏原中枢）；
  - `2` = 等待回调；
  - 两者叠加即"中枢中继"。

### 4.4 1+2 之后的回调分支（第二轮讨论补充）

1+2 状态下等待回调，回调出现后只有两种标准结果：

| 回调结果 | 判定 | 状态走向 |
| --- | --- | --- |
| 回调**不进入**新中枢 | 3买卖点形成 | 标注"3买/3卖"，新中枢升格为"原中枢"，进入下一轮监控 |
| 回调**进入**新中枢 | 价格回到中枢内部 | 机械状态归 **0**（监控对象 = 新中枢），**但必须携带上下文警示**（见下） |

#### "回调进入新中枢"这一支的语义（用户明确：不能当普通0处理）

该分支包含**三种可能**，都属于被排除的复杂分支，不做深度推演：

1. **假突破**：1+2 那一笔对原中枢的破坏失败了；
2. **即将演化成中枢扩张**：新中枢与更大区间融合；
3. **走势类型可能完结**：向上走势类型走到头了。

**处理方式（建议方案，待确认）**：

- 状态机落点仍是 0（价格确实在新中枢内部）；
- 但提示必须带上警示标签，例如：
  > `当前：0 新中枢内 · 上次 1+2 破坏失败（警惕假突破 / 中枢扩张 / 走势完结）`
- 只保留背景信息供人判断，不继续往下推演。

## 五、明确排除的复杂情况

以下情况**一律不在本系统处理范围内**，原因：本系统只做**标准的 2、3 买卖点**，逻辑链条走不到这些分支；若强行推演，会失去"只推一步"的简洁性，且对实际交易没有增量价值。

- 中枢**扩展**
- 中枢**扩张**
- 中枢**延伸**（第三笔未破坏原中枢后形成的更复杂结构）
- 背驰后再背驰等多层嵌套

判断的唯一标准：**必须破坏前一个走势类型的最后一个中枢**。不满足就等，不推演。

## 六、前端展示方案

### 6.1 展示拆分原则（已与用户确认）

信息分两层，重要性和实时性不同：

| 层 | 位置 | 性质 | 内容 |
| --- | --- | --- | --- |
| **K线图标注** | 图表上 | **最实时、最当下**，看盘第一眼 | 中枢区间、1/2/3 标记、买卖点、背驰破坏点 |
| **角落状态文本** | 图表左上/右上 | 关键说明，但不需在图上实时盯 | 当前状态徽章、流程 mini 导航、下一步提示 |

- K 线上的东西 = 一眼能感觉出来的，最重要；
- 角落文本 = 补充说明性质，也实时，但不是图形层面的关注焦点。

### 6.2 K 线图标注（核心）

以下标注直接画在 K 线上，用价格位置说话：

1. **中枢区间背景块**
   - 半透明矩形覆盖中枢区间（最高点~最低点）；
   - 上沿/下沿用实线描边，作为 2买卖点 的参考边沿。

2. **"1" 离开点标注**
   - 离开中枢的那笔起点处标注 `1`；
   - 根据离开幅度与中枢大小的关系，可加辅助说明（如 `1<`、`1>`）。

3. **"2" 回调笔标注**
   - 反方向回调笔**刚形成**的瞬间，在该笔上标注 `2`；
   - 颜色与"1"区分（如蓝色）。

4. **3买卖点标注**
   - 回调不进原中枢时，在回调笔终点标注 `3买` / `3卖`；
   - 用醒目颜色（红/绿）。

5. **2买卖点标注（边沿参考）**
   - 当价格处于中枢内部、且流程指向"参考原中枢边沿"时：
   - 在**中枢上沿/下沿**画一条短横线或虚线箭头，提示"此处为2买卖点入场位"；
   - **提示在中枢内即触发，不等价格到达**。

6. **背驰破坏点标注**
   - 情况 A（第一笔直接破坏原中枢）：在该笔终点标注 `2`（因为下一步只能是回调）；
   - 情况 B（第三笔破坏原中枢、有新中枢支撑）：标注 **`1+2`**，并可同时框出新中枢，表达"中枢中继"。

### 6.3 角落状态文本（辅助）

放在 K 线图左上角（或右上角），包含三部分：

1. **当前状态徽章**
   - 示例：`当前：1 离开中枢（幅度>中枢）`
   - 用颜色区分状态：0 灰、1 黄、2 蓝、买卖点红/绿。

2. **流程 mini 导航条**
   - `[0]中枢内 → [1]离开 → [2]回调 → [3]买卖点`
   - 当前节点高亮，下一步节点虚线框。

3. **下一步提示卡片**
   - 一句话或两三行列表：
   ```
   下一步：
   · 若回调不进中枢 → 3买
   · 若回到中枢内部 → 归 0
   ```

### 6.4 背驰分支的展示

- 情况 A：徽章显示 `2（等回调）`，K 线上标注破坏笔终点 `2`。
- 情况 B：
  - 新中枢画背景块（原中枢内部下方）；
  - 第三笔破坏原中枢时标注 `1+2`；
  - 角落提示：`当前：中枢中继（1+2） · 等待回调；若回调不进新中枢 → 3买卖点`；
  - 若随后回调进入新中枢：状态归 0 并显示警示标签（见 4.4 节）。

## 九、参考库（chanpy_review）中枢实现分析（2026-10-04 晚）

### 9.1 参考库有哪些中枢开关（`ZS/ZSConfig.py`）

| 开关 | 含义 | 与本项目理念的关系 |
| --- | --- | --- |
| `need_combine` | 相邻中枢是否合并 | ❌ 对应流程图排除的"中枢扩张" |
| `zs_combine_mode`（zs/peak） | 合并模式：区间重叠合 / 极值重叠合 | ❌ 同上 |
| `one_bi_zs` | 允许一笔成中枢 | ❌ 与"三笔重叠"定义冲突 |
| `zs_algo`（normal/over_seg/auto） | 构造算法 | normal 依赖线段 ❌；over_seg 纯按笔 ✓ |

### 9.2 关键发现（2026-10-04 晚二次核对修正）

1. **normal（默认）= 两笔成枢 + 线段内**：按线段把笔切段，段内与线段同向的笔直接跳过，剩余相邻**两笔**区间重叠即立枢；中枢区间=两笔重叠区，成枢后固定；后续笔与区间重叠即延伸（只延长结束笔）。
2. **over_seg = 三笔成枢 + 无线段**（首版分析漏讲，已修正）：纯笔序列滚动扫描，自由列表攒够**三笔**，`min(高点)>max(低点)` 即成枢；中枢区间=三笔重叠区 `[max(低点),min(高点)]`，成枢后固定；后续笔重叠即延伸。唯一线段残留：成枢三笔的第一笔若与其所属线段同向则放弃本次成枢（防边界守卫；本项目无线段，去掉即可）。**与本项目定义几乎一致**。
3. **auto**：按线段是否确定动态混用前两者。

### 9.3 与原著对照（结论：用户定义最接近原著）

原著第17课定义："某级别走势类型中，被至少**三个连续次级别走势类型**所重叠的部分"。三要素：①至少三个 ②连续 ③次级别走势类型重叠。

| 方案 | 与原著关系 |
| --- | --- |
| **用户：三笔重叠**（笔=次级别单元的简化，即"笔中枢"） | 原文定义的 1:1 直译，**最接近** ✅ |
| chan.py over_seg：三笔重叠+线段方向守卫 | 接近原著，次之 ✅ |
| chan.py normal：两笔成枢+线段内 | 砍掉"三个"、锁进线段，是为递归框架（笔中枢→线段→更高级别）做的工程妥协，**离原著最远** ❌ |

原著第20课：中枢延伸期间 [ZD,ZG] 不变（围绕区间震荡即延伸）——本项目方案与 chan.py 两种模式在这点上一致，无分歧。

### 9.4 有效性评估

- normal 在它自己的递归框架里自洽（信号早、中枢多、多级别对齐），但：① 依赖整个线段引擎（本项目无）；② 两笔成枢中枢更多更碎、噪声大；③ 用户流程图的几何约束（如"背驰分支新中枢一定在原中枢下方"）全部建立在三笔重叠的标准结构上，换两笔成枢则推导不成立。
- **结论：按用户的三笔重叠实现**（= 原著直译 ≈ chan.py over_seg 去守卫）。"两笔成枢"将来可做成**默认关闭的开关**供实验对比。

### 9.5 本项目的实现方案（已实施，2026-10-04）

在 `chanlun/` 新增 `zs.py`，不抄参考库算法、只参考结构：

1. **三笔重叠成枢**：相邻三笔端点区间有公共重叠（`min(高点) > max(低点)`）→ 成枢；
2. **中枢区间 = 成枢三笔的重叠区** `[max(三笔低点), min(三笔高点)]`，成枢后固定（对应缠论 ZG/ZD 定义，延伸笔只延长中枢、不改区间）；
3. **成枢后保留 end_bi**：成枢三笔的最后一笔（`end_bi`）不丢弃，保留在自由窗口中作为下一中枢的第一笔候选。对应用户指出的“离开中枢的笔应成为下一中枢起始笔”；
4. **延伸**：后续笔与区间重叠 → 延长结束笔，区间不变；
5. **进入笔** = 成枢三笔之前那笔；**离开笔** = 第一笔与区间不重叠的笔；
6. **不看线段、不看次级别**；
7. **笔变中枢自动变**：中枢每次请求都从最终笔列表现算，改笔开关 → 笔形变 → 中枢立刻跟着变；
8. **开关（全部进 ⚙ 面板新增“中枢”分组，默认=标准缠论，非默认时 ⚙ 带金点）**：
   - `zs_extend` **中枢延伸**（默认开）：成枢后后续笔与区间重叠则延长结束笔；
   - `zs_merge` **中枢合并**（默认关）：相邻中枢区间重叠时合并成一个（中枢扩张式）；
   - `zs_first_bi` **首笔成枢**（默认关）：允许第一笔就作为中枢起点（数据开头笔不完整时防止误判，参考 chan.py 同款守卫）。
