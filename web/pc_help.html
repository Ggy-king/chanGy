一、缠论 · 笔

"笔" 是缠论结构的最小单位：由相邻的一个顶分型和一个底分型连接而成。以下 6 个开关控制"什么样的顶底分型之间才能被认定为同一笔的两端"。

1. 笔算法 UI 选项：常规 / 分型 默认：常规
代码参数：bi_algo 参考项目默认值："normal" 对应文件：ChanConfig.py:24
缠论层面

成笔前是否要求"跨度"——两个分型之间必须隔着一定数量的 K 线，否则视为噪音，不成笔。

  • 常规：必须满足跨度要求，笔更粗、更少，过滤毛刺。
  • 分型：只要出现一对相邻的顶/底分型，就直接视为一笔起点和终点，笔更密、更短。
代码层面

在 chanlun/bi.py 的 _try_add_bi 中，若 bi_algo == 'fx' 则跳过 _satisfy_bi_span() 检查；否则必须满足 MIN_BI_SPAN 或宽松笔的跨度条件。

为什么默认是「常规」？

参考项目 chan.py 把 "normal" 作为默认，代表作者倾向于"有跨度的笔"，避免分型一现就画笔导致图形过碎。"fx" 是留给想要更多信号、更短笔的备选。

2. 笔型 UI 选项：严格 / 宽松 默认：严格
代码参数：is_strict 参考项目默认值：True 对应文件：ChanConfig.py:25
缠论层面

区分缠论里的"老笔"与"新笔"流派。

  • 严格（老笔）：一笔内部至少包含 4 根合并 K 线的跨度，笔更粗、更稳定。
  • 宽松（新笔）：跨度 ≥ 3 根合并 K 线，且两分型之间的原始 K 线 ≥ 3 根，笔更细、更多。
代码层面

MIN_BI_SPAN = 4。严格模式下 _satisfy_bi_span 检查 span >= 4；宽松模式下检查 span >= 3 且 raw_kl_cnt >= 3（对应 ChanConfig.py 中 bi_strict 语义）。

为什么默认是「严格」？

chan.py 默认走老笔逻辑。老笔在缠论传统教材中更常见，结构更稳定；新笔是部分现代实现的简化，笔更多但噪音也多。

3. 分型校验 UI 选项：松 / 半 / 严 / 全 默认：严
代码参数：bi_fx_check 参考项目默认值："strict" 对应文件：ChanConfig.py:26 / KLine/KLine.py
缠论层面

检查相邻两个分型之间的"价格重叠区域"，决定它们能否被认定为同一笔的两端。越严，两个分型必须拉得越开，笔越少。

  • 松（loss）：只比较分型自身那一根 K 线的价格，最易成笔。
  • 半（half）：各自向对方扩半边（±1 根里取一半区域）进行比较。
  • 严（strict）：双方前后各扩一根 K 线，3 根全比。参考项目默认。
  • 全（totally）：两个分型区间必须完全不重叠，最难成笔。
代码层面

对应 chanlun/bi.py 中的 _fx_valid()，逐行移植自 chanpy_review/KLine/KLine.py::check_fx_valid()。四个模式分别对应 loss / half / strict / totally，其中 strict 与 totally 取同一扩展区间，但 totally 进一步要求 a.low > b.high（或反向），即分型区间无重叠。

为什么默认是「严」？

参考项目原作者在 ChanConfig.py 中把 bi_fx_check 设为 "strict"。这是一种折中：比 "loss/half" 更能过滤假笔，又不像 "totally" 那样苛刻导致大量本可成笔的结构被丢弃。

4. 端点极值 UI 选项：开 / 关 默认：开
代码参数：bi_end_is_peak 参考项目默认值：True 对应文件：ChanConfig.py:28
缠论层面

一笔的起点和终点是否必须是从起点到终点这段区间内的最极端价格。开着更严格：顶必须是区间最高点，底必须是区间最低点；关了允许端点不是区间极值。

代码层面

在 chanlun/bi.py 的 _try_add_bi 中，若 bi_end_is_peak=True，新加入的潜在端点会被要求高于/低于区间内所有合并 K 线的对应极值。

为什么默认是「开」？

标准缠论定义中，一笔的端点应包含该笔范围内最极端的价格。开着保证端点的几何意义，关着则会让端点可能落在次高/次低，结构会显得"歪斜"。

5. 次高点 UI 选项：允许 / 回退 默认：允许
代码参数：bi_allow_sub_peak 参考项目默认值：True 对应文件：ChanConfig.py:29 / Bi/BiList.py
缠论层面

当后面出现一个比前面分型更极端的新分型时，前面那个次高/次低点怎么处理。

  • 允许：次高点/次低点直接独立成笔。笔更密，更早出现。
  • 回退：次高点暂时不成笔，启用 update_peak 机制，把后续更极端的分型拉回来，让笔的端点向后延伸。笔更少、更"完整"。
代码层面

chanlun/bi.py 在 _try_add_bi 中，若 bi_allow_sub_peak=False 且当前分型比前一笔的端点更极端，则调用 _update_peak() 把前一笔的端点"更新"到当前分型（即回退延伸）。移植自 chanpy_review/Bi/BiList.py::update_peak()。

为什么默认是「允许」？

chan.py 默认允许次高点成笔，这样每一根明显分型都能及时形成一笔，图形更连续。"回退"模式更像某些保守实现，只在更极端分型确认后才固定端点。

6. 缺口算K UI 选项：开 / 关 默认：关
代码参数：gap_as_kl 参考项目默认值：False 对应文件：ChanConfig.py:27
缠论层面

两个合并 K 线之间若出现跳空缺口，在判断笔的"跨度"时，是否把缺口折算成一根 K 线。开着：跳空可补足跨度，某些因跳空而"缺 K"的结构也能成笔；关着：只按实际 K 线数量算。

代码层面

chanlun/bi.py 中的 _has_gap_with_next() 检测缺口，_get_klc_span() 在 gap_as_kl=True 时把缺口加 1 计入跨度。对应 chanpy_review/Common/func_util.py 中的缺口处理逻辑。

为什么默认是「关」？

chan.py 把 gap_as_kl 默认设为 False，表示作者保守处理：缺口是否成笔有争议，默认不把它当一根真实 K 线。只有在明确认同"跳空等于一根 K" 的流派时才打开。

关于默认值：页面顶部「⚙」按钮右上角出现金色小点时，表示当前至少有一项偏离了上述默认。点击「恢复默认」可一键回到 chan.py 原版配置。

二、缠论 · 中枢

"中枢" 是多空反复交战的价格区间：图上以上下两条金色虚线标出区间上沿（ZG）和下沿（ZD）， 左端就是起始笔的起点，一眼可看出中枢从哪开始。中枢由本级别的笔直接构成（笔中枢）， 不使用线段、不使用次级别走势类型。以下 3 个开关处理成枢前后的边界情况。

为什么用笔而不用"次级别走势类型"？ 原著中枢定义是"至少三个连续次级别走势类型的重叠"，但"本级别的次级别到底对应哪个K线级别" 在原著中是模糊的、无法落实的。因此任何用"次级别走势类型"模拟本级别中枢的做法都不可靠， 唯一可落地的做法就是用本级别的笔作为构成单元——三笔重叠即成枢。
中枢延伸 参数 zs_extend 默认：开
算法位置：chanlun/zs.py → build_zs() 默认值 = 开（缠论中枢延伸）

成枢之后，凡是与中枢区间 [ZD, ZG] 有重叠的后续笔，都会延长中枢的结束笔——但中枢区间本身永远不变（对应原著 ZG/ZD 一旦确定、延伸期间围绕区间震荡的定义）。

缠论层面

图上看到的：中枢的两条金色虚线越拉越长，价格在里面来回震荡多久，中枢就延伸多久；直到出现一笔完全走出区间，中枢才完结（这一笔即"离开笔"）。

代码层面

zs_extend=True 时，后续笔区间与 [low, high] 有交集 → 只更新 end_bi；关掉后中枢固定为成枢三笔，下一笔即判为离开。

为什么默认开

中枢延伸是标准缠论概念（第20课），关掉会导致大量本该属于同一中枢的震荡被拆成多个小中枢。

中枢合并 参数 zs_merge 默认：关
算法位置：chanlun/zs.py → build_zs() 尾部合并段 默认值 = 关 参考 chan.py CZSConfig.need_combine + zs_combine_mode='zs'

相邻两个中枢的区间有重叠时，把它们并成一个大中枢：区间取并集，结束笔取后者。

缠论层面

对应"中枢扩张"式的处理：前后两个中枢价格区域咬合，视为同一个更大的交战区域。

代码层面

逐个扫描已成的中枢，前一个区间 [p.low, p.high] 与后一个有交集 → 合并（low=min、high=max、end_bi=后者，merged_count 记录合并了几个）。

为什么默认关

标准 2、3 买卖点的推导都建立在"每个中枢独立"上；合并属于扩张类复杂情况，仅在你想观察大级别交战区域时打开。

首笔成枢 参数 zs_first_bi 默认：禁止
算法位置：chanlun/zs.py → build_zs() 成枢守卫 默认值 = 禁止（与 chan.py 禁止 begin_bi.idx==0 成枢 一致）

是否允许数据里第一笔就作为中枢的起点（起始笔）。

缠论层面

图最左边的前三笔若重叠，默认不算中枢——因为第一笔之前没有"进入笔"，结构不完整。

代码层面

成枢窗口的第一笔下标为 0 且本开关为"禁止"时，跳过本次成枢，滑动窗口继续往后找。

为什么默认禁止

数据开头的笔缺少前文语境，极易误判；chan.py 也做了同样处理。

成枢规则（不可配置，固定为最标准缠论）
  • 相邻三笔端点价格区间有公共重叠（min(高点) > max(低点)）→ 成枢；
  • 中枢区间 [ZD, ZG] = 三笔重叠区，成枢后固定，延伸只延长结束笔；
  • 进入笔 = 成枢三笔之前那一笔；离开笔 = 第一笔与区间不重叠的笔；
  • 中枢每次都从最终笔列表现算：你在 ⚙ 笔设置里改任何开关，笔形一变，中枢立刻跟着变。
